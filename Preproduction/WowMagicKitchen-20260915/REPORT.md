## 锁定的视觉规则

- 固定正交，目标俯角 50°，不旋转。预览的平面投影采用对角 45°；生成目标图的相机角度只是提示词约束，不能反推为精确相机矩阵。
- 640×360 逻辑预览；厨师 64×64 逻辑画布，身体高度 50 px，四向脚底统一在左上原点坐标 `(32,58)`。建议先试 32 PPU。
- 原创年轻厨师：棕色短发、奶油短弯尖厨师帽、陶土帽带与领巾、短紫袍、奶油围裙和棕靴。帽尖和背面轮廓仍需人工统一。
- 奶油 `#F4E5C6`、蜂蜜 `#AD713C`、陶土 `#B9543E`、鼠尾草 `#8D9B72`、暗紫 `#51415F`、水色 `#65C7D1`。精灵统一映射到 28 色候选色板，单个厨师方向实际使用约 20–21 种实色。
- 背景装饰留墙边；特效主要在食物外缘。火、冰都保留像素区域 `x=10…21, y=6…22` 的透明窗。正常特效比事故特效矮，区别包含形状变化。
- 本轮未制作动态光照、Bloom、景深或雾，也没有在精灵上烘焙地板和大片投影。

## 实际观察与结论

**镜头清晰度：初步可用，尚未通过 Unity 验收。** A/B 的炉灶、L 柜台、窗、出餐口、岛台、厨师、史莱姆和食物的位置基本对应，B 的环境纹理更安静。两张概念图里的面包都被明显放大，不能仅根据它们判定实际食物可读性。浏览器几何预览使用导出的 32×32 食物检查，彩色和灰度下仍能凭高度、切口与裂纹识别三态。最终将生面团和焦面包压低，避免三态只有颜色差异。

柜台台面与生面团同为浅色，需要保留面团深色边缘。高对比棋盘地面仍稍显抢眼，量产时宜降低地砖对比或减少交替色。预览的材质图已经降低原始纹理变化，但未证明 Unity 中 Point 采样、阴影和缩放后的最终观感。

**角色一致性：身份基本保持，动画生产链仍需人工。** 四向身高都是 50 px，脚底一致；帽子、围裙、发型与服装颜色保持相同身份。问题是侧面仍偏立面，不能声称严格匹配 50° 俯视；背面帽尖和正侧向轮廓存在偏差。行走只做了原图分件位移，摆腿幅度小，仍有滑步；施法的肩部、袖口和手部转折偏硬。这里将其明确交付为待清理草稿。

跨帧稳定来自“同一源图复用”，不是模型连续独立绘制的稳定性。后续宜固定头、身体、手臂与脚的局部形状，先完成一个方向的正确步态，再扩展方向。本轮没有再制作其他角色或大量宠物帧。

**多人可读性：未通过。** 四人复用同母版进行占位检查时，身体轮廓可以看见，但玩家身份无法快速区分。下一轮应增加少量服装配色和同时具备形状差异的玩家标记；单靠颜色不够。本次没有扩展为多人玩法。

**模块化：成本较低的结构验证成立。** 3 个 OBJ 是独立简单盒体组合，各自带 UV 和材料引用，可移动、复制和摆放；不是从概念图抠出的场景切片。无需骨骼，未制作精细倒角。柜台 1×1 单位、顶面高约 0.89；地砖节距 1、实际宽 0.98 留缝；出餐口包含柱、横梁、台板和简化雨篷。尚未验证 Unity 的 OBJ 导入轴向、法线、材质路径和背面剔除；必要时在建模软件中确认后另存 FBX。

**宠物和特效：适合继续低成本验证。** 一张史莱姆就可以验证呼吸、弹跳与半透明；程序形变并没有增加动画贴图。正常冰缘在首次缩小时过于零碎，已去掉外围漂浮颗粒后重新取样。特效叠在食物上保留中央切口和裂纹，但冰事故侧柱在实际操作中仍需检查是否遮住邻近格子。

## 音乐制作与循环检查

两首都是本轮新写的主题、和声与音符事件，没有输入艺术家参考或现成音乐。音色是本地合成的拨弦、类单簧管、钢片琴与木质打击，不是实际乐手录音，也不是调用专门音乐生成模型。可以用它们判断主题、配器密度和节奏；真实室内乐的呼吸感、吉他的指板质感仍是后续音色制作课题。

主题骨架 MIDI 音高：`74,76,79,78,76,74,71,67`，G 大调。备店版本留出更多木管空隙，营业版本缩短旋律时值并提高拨弦与打击密度。最后半拍开始一个接续音，尾音延伸到下轮。不同 BPM 的两首并非天然无缝衔接，也不能直接叠加；预览页切换时停止前一曲。

| 检查 | 备店 A | 营业 B |
|---|---:|---:|
| 格式 | 48 kHz / Stereo / PCM16 | 同左 |
| 精确样本长度 | 2,048,000 | 1,675,636 |
| 理论 16 小节误差 | 0 sample | −0.364 sample（四舍五入） |
| 峰值 | −8.41 dBFS | −7.07 dBFS |
| 全曲 RMS | −21.00 dBFS | −21.00 dBFS |
| 削波采样数 | 0 | 0 |
| 接缝采样差最大值 | 0.00403 | 0.00217 |
| 接缝采样差相对日常 99% 分位变化 | 更小 | 更小 |
| 接缝前后各 100 ms RMS 差 | +1.87 dB | +1.03 dB |

初稿接缝前后短时能量差曾达到约 18.9 / 11.7 dB。通过增加乐句接续音并降低循环入口低音力度，改善为上表结果。没有使用整段淡入淡出，也没有截掉自然尾音；所有音符尾音与短房间反射都按精确循环样本数回绕。

节拍来自可检查的事件谱与 MIDI 节奏网格，样本长度与 16 小节严格对应；这不是对未知录音进行独立 BPM 识别。主 WAV 是单轮，三轮试听文件是样本级拼接。MIDI 补写了跨边界的延音段，换音源后仍需重新检查尾音与响度。

**验证边界：** 已做数值检查，并在浏览器验证音频载入、播放进度、停止与曲目切换。没有进行可声称为真人听感验收的反复聆听，因此不能将疲劳感、旋律感染力或“听不出接缝”标记为通过。请先各听三轮：记录是否能指出边界、是否觉得木管尖锐、第三轮是否想调低音量，以及是否干扰阅读订单。可用随包的分轨降低木管或钢片琴，不必重新生成整首。

## 单人开发的成本判断

本轮使用 8 次内置 ImageGen 调用：2 张概念对照、厨师四向、史莱姆、面包三态、火、冰和共用材质图。没有读取账单，不能给出这些调用的实际货币价格。音乐是本地运算，没有调用音乐生成 API；编曲和工具代码工作仍消耗本次 Codex 使用量，不能理解为整个过程零成本。

下面是**下一轮人工投入的规划范围，不是本次工时实测，也不是报价**：

| 工作项 | 预计人工修整预算 | 继续标准 |
|---|---:|---|
| 一个静态食物三态 | 20–45 分钟 | 原生尺寸、灰度下三态均能辨认 |
| 一个基础厨房模块 | 15–40 分钟 | 复制摆放无接缝，材质路径简单 |
| 一个单姿态宠物 | 15–30 分钟 | 缩放不破坏轮廓，表情清楚 |
| 一套正常 / 事故特效 | 20–45 分钟 | 食物中心可见，不越格遮住邻居 |
| 厨师四向 + 本轮两段动作清理 | 2–4 小时起 | 头身比例统一、脚底稳、肩部自然 |
| 两首音乐的听感与音色修改 | 1–2 小时起 | 三轮试听无明显烦躁，接缝和订单阅读通过 |

若厨师这一小套需要持续多轮重绘仍无法统一方向，应先降低动作数量，或把角色表现改为更易复用的有限方向；不要在未解决母版时扩展角色库。B 的优势主要在环境结构和材质能重复使用，角色动画仍是工期风险。

## Unity 首次导入建议（未执行）

1. 将需要测试的 `sprites`、`modules` 和两首主 WAV 复制到一个独立测试资源目录。不要把 `concepts`、源图或全部多轮试听文件当成运行时资源。
2. 厨师 PNG：Sprite、Point、关闭压缩和 Mipmap，先试 32 PPU；图集按 64×64 网格切片，固定 Pivot `(0.5,0.09375)`。11 帧横向图集为 704×64。具体帧范围见 `manifest.json`。
3. 食物：32×32，Pivot `(0.5,0.1875)`；史莱姆 `(0.5,0.125)`；魔法 `(0.5,0.09375)`。精灵外侧透明，史莱姆内部还包含半透明像素；不要给所有精灵套同一套硬 Alpha 裁切。
4. 为角色使用朝固定相机的精灵平面，逻辑移动在地面；台面上的食物高度与柜台顶面一致。先检查前后遮挡与脚底接触，再增加灯光。单纯设置相同 Sorting Order 不能证明与立体台面正确遮挡。
5. 正交相机目标俯角 50°。在 360 像素逻辑高度、32 像素/世界单位的测试下，Orthographic Size 起点约 5.625。相机朝向、位置与裁剪范围需在 Unity 中校准，不能直接把概念图当作标定数据。
6. OBJ 与 MTL、4 张纹理放在相同目录中；按当前渲染管线创建合适的材质。导入后确认法线、面朝向、UV 与 1 单位地砖节距。此处没有替项目修改 Package 或渲染管线。
7. 音乐首测保留 PCM，关闭归一化处理，按整段样本循环。切换两首需要另外设计拍点或过渡，不能假设不同 BPM 的文件可直接无缝切换。压缩格式和 Streaming 设置留到目标平台验证时决定。

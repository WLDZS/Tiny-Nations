# 导航测试场景

`NavigationTest` 是寻路查询和真实单位移动的固定夹具。它不加载 Demo 的装饰或预放置单位，避免演示场景的修改改变测试条件。场景仅有相机、`World/Grid/Ground`、`World/Grid/Collision` 和挂在 `World` 上的 `NavigationTestPanel`。从主菜单进入后，场景状态启动导航与单位系统；按 Esc 返回主菜单。面板顶部可切换四个观察区域，选中用例时镜头也会定位到对应区域。

## 地图约定

- Grid 每格为 1 个世界单位。原测试区保留 `x=-12..11, y=-8..7` 的 384 格；右侧新增 3 个独立区域，每区 112 格。Ground 共 720 格，Collision 共 85 格。
- `#` 是 Collision，不可行走；`.` 是 Ground，可作为导航格。图中从上到下是 `y=7..-8`，从左到右是 `x=-12..11`。
- `Collision` 使用 `TilemapCollider2D` 和本场景专用的 Grid Collider Tile，每个障碍占满一格；测试场景开启其红色渲染，以便直接对照路线。净空半径按世界单位计算。地图和固定用例互相绑定，若要改布局，应同步调整用例与夹具校验。

## 固定查询

右侧面板的“运行全部固定用例”执行 20 项同步查询。每项对比预期与实际 `EPathQueryStatus`，还检查失败路径为空、成功路径的精确终点、路径分段是否穿过障碍或净空不足，并记录路点数、路径长度和单次查询耗时。点击某项可单独重跑和显示对应路径。“连续回归 20 轮”会执行 400 次查询，统计失败次数、总耗时和单次最长耗时，用于发现连续请求间的状态污染；耗时是当前机器的调试参考值，不是跨设备性能门槛。

| 类别 | 用例 | 预期 |
| --- | --- | --- |
| 基础 | 直线、同格精确终点、导航锚点偏移 | `Success`，终点等于请求坐标 |
| 绕障 | 矩形障碍、对角穿角 | `Success`，实际路径长于直线 |
| 净空 | 1 格通道，半径 0.2 / 0.55 | `Success` / `InvalidStart` |
| 无效端点 | 障碍起点、障碍终点、地图外终点 | `InvalidStart` / `InvalidDestination` |
| 不可达 | 封闭区域内的有效目标 | `NoPath`，无路点 |
| 靠近 | 障碍目标调用 `FindApproachPath` | `Approach`，终点在目标附近 |
| 独立性 | 障碍边缘 A、B 反向连续查询 | 两次均 `Success` |
| 复杂障碍 | 散障碍区、曲折通道、死胡同 | `Success`，路径绕行且每段净空合法 |
| 区域分离 | 从原地图向右侧独立区域查询 | `NoPath`，无路点 |
| 复杂端点 | 散障碍旁大半径起点、靠近障碍目标 | `InvalidStart` / `Approach` |

地图中的绿色 `S` 为起点，红色 `T` 为请求目标，黄色折线为返回路点，蓝色 `A` 为靠近时的实际终点。可在“自由查询”中点选世界坐标、调整净空半径，并选择是否允许靠近目标。

## 实际单位测试

右侧面板切换到“实际单位”，可运行下列具体兵种用例。下表的单单位用例每次先生成一个静止的 WarriorBlue 目标（TeamId 2，玩家输入模式），再生成 TeamId 1 的 AI 单位；“障碍旁有其他单位”会额外生成一个静止的同队 WarriorBlue。AI 通过现有目标搜索、`UnitNavigationLogic` 和 `UnitMovementLogic` 行走，不使用面板画出的查询路径代替移动。切换用例或点击“清理测试单位”会回收本面板生成的单位。

| 移动单位 | 场景 | 要验证的行为 |
| --- | --- | --- |
| WarriorBlue | 开放区域 | 能生成、获取目标并开始移动 |
| WarriorBlue | 绕开中央障碍 | 真实碰撞体随路径绕行，不进入阻塞状态 |
| WarriorBlue | 一格通道 | 用预制体实际净空通过通道 |
| WarriorBlue | 障碍旁有其他单位 | 一个单位紧贴障碍时，另一单位仍能查询并移动 |
| Spider | 大半径绕障 | 第二种单位用更大的身体半径和不同导航锚点绕开障碍 |
| WarriorBlue | 散障碍区 | 连续避开多个障碍并追近目标 |
| WarriorBlue | 曲折通道 | 从相反方向的两个开口折返穿行 |
| WarriorBlue | 死胡同出口 | 不穿过侧墙，从下方出口绕向目标 |

多单位压力测试提供两个按钮：

| 模式 | 场景布置 | 判定重点 |
| --- | --- | --- |
| 20 单位 → 同一目标 | 开放区中 20 名 WarriorBlue AI 排成 5×4 队列，全部追向同一静止目标 | 同一帧段内观察错身、目标周围分布和重叠对数 |
| 20 单位 → 不同目标 | 原地图上方、下方各 10 名 WarriorBlue AI，分别追向各自区域的静止目标 | 观察两个方向的避让与目标周围分布，确认互不串目标 |

测试先生成全部 20 名移动单位，此时场景中没有敌方目标；随后才生成 1 或 2 个目标，让 AI 集中开始寻路。测试期间临时关闭目标预制体的 `Hurtbox`，避免近战攻击提前击败目标；清理时恢复其原状态，再将单位交还对象池。目标的身体碰撞体仍保留。地图上绿色圆点追向红色 T1；不同目标模式的蓝色圆点追向红色 T2。追击者通过 UnitApproachSlots 领取稳定的近处或外围位置，外围位置到达后等待近处空位，而不再反复向目标精确坐标挤压。面板显示每名单位的移动距离、导航状态、最近查询状态，以及目标附近人数和重叠对数。20 名单位都经历 `Following` 与 `Success`、实际行走至少 0.75 世界单位，有至少 2 名单位进入目标 1.25 世界单位内，且没有导航阻塞，并在至少 4 秒观察期后没有间距小于 0.55 世界单位的单位对，才显示通过。目标 `Hurtbox` 被关闭时，近战 AI 不会因进入攻击范围而停下；这时近处两名单位也会到位等待。身体碰撞仍相互忽略，重叠对数是实际运动效果的检查，而不是物理碰撞保证。

单单位用例持续显示单位 `WordPos`、导航状态、最近查询状态和阻塞原因。一个单单位用例只有在导航进入过 `Following`、返回过 `Success`、实际移动超过该用例的最小距离，并靠近目标至 1.6 世界单位内时才标记“通过”；发生 `Blocked`、单位消失或超时会标记失败。这里的“通过”代表 AI 已完成有效追近，**不代表到达敌人精确坐标**：近战 AI 会在攻击范围内停止寻路。目标使用玩家输入模式以保持静止，运行这些用例时不要按移动键。

在 Editor / Debug 构建中，左侧原有单位调试面板仍可打开导航网格、绘制单位坐标或自行生成额外单位。额外生成的敌对单位会改变 AI 选目标，因此固定单位用例应在未手动生成其他单位的干净场景中运行。

## 验收步骤

多单位面板会在导航状态旁标记“近处位置”“前往外围”或“外围待位”，便于区分主动等待与寻路阻塞。

1. 从主菜单进入导航测试，用面板顶部按钮观察原地图、散障碍区、曲折通道和死胡同；确认红色碰撞格与不同地面区域可见。在“寻路查询”页运行全部 20 项固定用例并查看通过数。
2. 点开绕障、窄通道、封闭区域、曲折通道和死胡同用例，核对绿色/红色标记、黄色路径与状态；将自由查询终点放在障碍上，再切换“尝试靠近”比较结果。
3. 切换到“实际单位”，逐项运行 WarriorBlue、Spider、障碍旁单位及三个新增环境用例。再分别点击“20 单位 → 同一目标”和“20 单位 → 不同目标”，观察途中错身、目标周围排布和面板重叠对数；确认没有持续重叠且最终显示 20/20 通过。若失败，记录重叠对数、未完成移动单位的查询状态和阻塞原因。
4. 按 Esc 返回菜单，再次进入，确认测试单位已清理且固定查询仍可执行。

源码与场景序列化检查不能替代 Unity 编译、Play Mode 和视觉结果；这些步骤由开发者在编辑器中执行。

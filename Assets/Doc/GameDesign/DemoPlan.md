版本：0.1 · 2026-09-22。本文件区分当前事实、拟开发目标和未来实测；不表示下面各阶段已完成。

## 1. 两人Demo最终交付边界

| 内容 | 两人Demo要求 | 后续完成版 |
| --- | --- | --- |
| 对战 | 1v1创建/加入/准备/加载/开局/结算 | 2v2，最多4名玩家 |
| 数量 | 每玩家共享20人口，各兵种无独立数量上限；两方最多40个可控对象 | 同规则，四方最多80个可控对象 |
| 单位 | 蓝红工人、战士、弓手 | 加入长枪兵、修士，增加紫黄素材装配 |
| 经济 | 金木、自动往返、固定容量住宅、外部仓库 | 沿用，不追加食物、维护费和贸易 |
| 建筑 | 城堡、兵营、靶场、住宅、仓库，预设地块 | 修道院和限一座的固定塔位 |
| 科技 | 一次军备升级 | 沿用，不扩成科技树 |
| 控制 | 选择/框选、右键上下文、直接撤退、停止、回城；可选编组 | 沿用，加自动治疗 |
| AI | 自动接敌、目标保持、有限追击、基本分离 | 同规则扩充新单位，非电脑对手 |
| 地图 | 1张对称1v1地图，开放信息 | 1张2v2地图；迷雾另评估，不绑死首个4人测试 |
| 结束 | 城堡摧毁、投降、20分钟比较城堡比例 | 队伍胜负，仍最多20分钟有效时间 |
| 表现 | 现有素材、清晰血条、箭矢、受击闪色、烟尘 | 沿用，接入已有治疗特效 |

不进入本轮：新种族、英雄、野怪成长、海战、空战、装备、技能快捷栏、自动战略AI、排位、观战、重连恢复、主机迁移、新美术制作。既有其他生物和资源不会删除，只不属于本版玩法承诺。

## 3. 按依赖推进，不一次性改完整游戏

### 阶段A：收口已有战斗，形成可控部队

先让蓝红战士和弓手能被选择、下令、接敌、单体攻击、死亡。接通弓箭，明确一次命令、一次命中、一次死亡；验证基本单位分离和地形通行。目标是两组约10人能前进、打起来、整队撤退，且攻击移动不会抢走撤退命令。

验收：相同指令下没有群伤误结算、穿身、无限追击、取消后摇无限攻击或池化残留。先采用策划初值测试行为，不靠新增兵种解决基础问题。

### 阶段B：尽早完成两台机器的最短对战

在扩经济前，完成创建/加入/准备、蓝红归属、统一命令和一致伤害、一次胜负结算。可以用固定初始部队和城堡做短技术测试；此阶段**不是**15–20分钟游戏Demo。

网络同步方案先单独决策和验证：若选确定性帧同步，需要验证当前物理、浮点、事件顺序能否满足要求；若选权威状态同步，也必须验证客户端不能自行扣血、扣钱或生成军队。策划不混用两条技术路径，也不声称已经安装联网组件。

验收：两台机器看到相同归属、HP、死亡、单位数量和结局；移动与攻击重复输入不会重复执行。不要先把全部经济做成本地逻辑，再最后“加联机按钮”。

### 阶段C：经济与固定地块

接工人自动采金伐木、交付、人口、住宅、兵营/靶场生产、外部仓库和点地块派工。所有新增操作从一开始纳入同一对战命令路径。

验收：新手不靠开发者说明也能看到资源、人口和按钮不足原因；开局不软锁；施工归岗、资源耗尽、工人被杀、住房被毁和出兵口堵塞均有明确行为。

### 阶段D：完成一局15–20分钟

制作“林间对峙”地图，接一次军备升级、回城休整、900秒决战、1200秒结算与结果页。覆盖各色美术、UI和死亡表现，记录经济与交战节奏，再决定初值调整。

验收：完成下方对局记录，不把一次完整跑通等同于平衡完成。首个可玩的两人Demo以本阶段为范围终点。

### 阶段E：在已有素材内完善阵容与四人

先加长枪兵和自动治疗修士，复核满人口下的配兵价值与治疗强度，再增加2v2地图、队伍归属、紫黄色和四机房间。防御塔最后评估，若它让比赛明显变慢，可保持关闭，无需为了用完素材强行加入。

验收：四名玩家无法控制队友或对手资产，队友治疗和无友伤成立；一位玩家被淘汰后其队友仍可继续；全队淘汰与同帧城堡互毁结算一致。四人数量与地图需重新验证，不能沿用两人帧率推断结果。

## 4. 新手教学只教五件事

1. 看见工人已经在工作，知道顶部金币、木材、人口是什么。
2. 点击标好的兵营地块，按建造；完成后点击训练战士。
3. 框选军队，右键地面前进，遇敌自动战斗；右键敌人可以集火。
4. 点“回城”或右键己方城堡撤回休整；不要求逐个点残血或开技能。
5. 人口不足时点住宅地块；安全矿耗尽时，框选闲置工人右键外矿。

第一轮提示随玩家真实完成动作消失，不连续弹出多页说明。总计目标在3分钟内让首次体验者造出士兵并主动发出一次进攻/回城指令；失败优先修改交互和提示。

## 5. 未来必要验收场景

| 场景 | 验收结果 |
| --- | --- |
| 首次进入房间，两人同时点击准备或重复发送开始 | 只开一局，身份与资源完全一致 |
| 20人口附近两建筑同时入队 | 统一预占人口，不超生、不部分扣钱 |
| 10工人10军人、20工人、20军人、大量修士等极端配兵 | 仅受共享人口、资源与前置建筑限制，不存在隐性兵种人数配额；数值问题通过平衡解决 |
| 住房被摧毁，已有军队和已付费队列超出当前容量 | 不删除活人；待产单位等待容量；重建后恢复 |
| 工人建造、运送途中被杀；矿枯竭；仓库被摧毁 | 资源不复制、不负数；工作按合同切换或提示 |
| 金币不足且全部工人死亡 | 紧急招工每人仅一次；不能取消免费项目套现 |
| 10–16人同时过窄口、拐角、包围目标 | 不叠成一点、不卡死、不穿敌人；失败有明确停止 |
| 前进交战中点击回城 | 当前未命中攻击取消，部队沿途不再自动接敌 |
| 双段近战、弓箭在途、同帧治疗和致死 | 伤害次数符合定义；死亡只一次；两端结果一致 |
| 城堡外缘射击 | 不存在弓手靠建筑半径额外无伤拆城 |
| 双方城堡同一步归零；1200秒边界击杀 | 先结算本步死亡，再确定胜负；不按客户端先后顺序 |
| 失联、房主退出、投降 | 按已定义冻结/技术负/中断规则显示，不伪造同步成功 |
| 两人40对象/四人80对象，叠加箭与特效 | 选中轮廓、血条和玩家色清楚；无持续重叠与大片烟尘遮挡 |

性能目标先以项目实际测试机、分辨率与画质为基准记录：期望1080p下稳定60FPS，并记录CPU/GPU帧耗、单位峰值和网络延迟；未指定最低硬件前不承诺全设备60FPS。联网应至少分别测试低延迟、模拟约100ms往返延迟及轻度丢包；正确性优先于先对外承诺某个延迟指标。

## 6. 首轮对局记录与平衡目标

先完成至少10局有效1v1，其中包含至少4局首次体验者参与的教学观察；掉线和规则Bug局单独记录，不混入时长平均。样本只用于发现明显问题，不宣称统计上已证明平衡。

| 记录项 | 目的 / 初期目标 |
| --- | --- |
| 规则版本、地图、双方熟练度、房主/客机 | 避免把技能差距和网络差异当兵种不平衡 |
| 首个自造士兵、首次交战时间 | 新手3分钟内能操作生产；正常首战约3–5分钟 |
| 5/10/15分钟的资源、人口、军队构成 | 验证6–10分钟形成主要军队，是否大量攒钱不会花 |
| 安全矿耗尽、第一座外部仓库时间 | 验证地图资源能引导中期冲突 |
| 每次交战时长、损失、撤回数量 | 大多数主战斗希望15–35秒；大量小于5秒要先查群伤和叠人 |
| 空闲工人、生产停滞原因、误触/无法理解操作 | 易上手比更多主动技能优先 |
| 结束时间、摧城/投降/超时/中断原因 | 势均力敌完整对局中位数目标15–20分钟；尽量让多数由摧城结束 |
| 新手能否仅用基础鼠标操作完成一局 | 不以必须编组、逐个拉兵或手动技能为通过条件 |
